# EasyTier 安装与管理脚本

面向 OpenWrt、ImmortalWrt 及常见 Linux 系统的 EasyTier 交互式安装管理工具。脚本负责下载和管理 EasyTier 核心组件、选择运行模式、配置服务启动方式，并提供后续更新与卸载菜单。

> 本项目是第三方安装管理脚本，不是 EasyTier 官方项目。请在运行前检查脚本内容，并先在测试设备验证。识别到 CPU 架构不代表 EasyTier 官方一定提供相应可用的 Release 资产。

## 快速开始

在目标设备的 root SSH 终端中执行：

```sh
curl -fsSL "https://raw.githubusercontent.com/jhbook/easytier-installer/refs/heads/main/easytier.sh" -o /tmp/easytier.sh && sh /tmp/easytier.sh
```

如果设备没有 `curl`，可以使用 `wget`：

```sh
wget -O /tmp/easytier.sh "https://raw.githubusercontent.com/jhbook/easytier-installer/refs/heads/main/easytier.sh" && sh /tmp/easytier.sh
```

#### 国内网络访问方式

如果设备访问 GitHub Raw 较慢或失败，可以尝试通过镜像下载管理脚本：

```sh
wget -O /tmp/easytier.sh "https://jsd.onmicrosoft.cn/gh/jhbook/easytier-installer@main/easytier.sh" && sh /tmp/easytier.sh
```

也可以使用 `curl`：

```sh
curl -fsSL "https://jsd.onmicrosoft.cn/gh/jhbook/easytier-installer@main/easytier.sh" -o /tmp/easytier.sh && sh /tmp/easytier.sh
```

镜像服务的可用性可能变化；若下载失败，请改用 GitHub 原始地址或其他可信镜像。注意，管理脚本下载地址与 EasyTier 核心下载源不同：安装器会优先尝试 Gitee 上的 EasyTier Release，再尝试配置的 GitHub 镜像，最后回退 GitHub 官方 Release。

首次以 root 运行时，脚本会尝试将管理脚本安装到 `/usr/bin/et`。安装成功后，之后输入以下命令即可打开菜单：

```sh
et
```

也支持在有可用控制终端的交互式 SSH 会话中使用管道启动：

```sh
curl -fsSL "https://raw.githubusercontent.com/jhbook/easytier-installer/refs/heads/main/easytier.sh" | sh
```

管道启动依赖可用的控制终端；在 cron、后台任务或无终端容器中不能使用交互菜单。为便于区分下载失败与运行失败，建议优先使用“下载到文件再执行”的方式。

## 功能一览

- 自动识别常见 Linux 系统、服务管理方式和 CPU 架构。
- 提供本地 Web、本地 TOML 配置、远程 Web 三种运行模式。
- 安装、更新 EasyTier 核心和当前模式需要的组件。
- 管理服务启动、停止、重启、状态和日志。
- 编辑本地 TOML 配置、设置远程 Web 配置服务器。
- 修改运行参数：节点端口、Web/API 端口、配置服务端口、Web API 地址、局域网转发开关。
- 设置下载镜像，并按多个来源尝试获取 EasyTier Release。
- 从指定 GitHub 仓库更新本管理脚本，替换前检查脚本身份和 Shell 语法。
- 在 OpenWrt / ImmortalWrt（fw4 防火墙）上安装时可顺便开启局域网转发与 NAT，让局域网设备访问 EasyTier 网络。
- 运行状态可直接看到已连接节点、延迟与丢包，以及本机公布的路由与代理网段。
- 主菜单顶部与菜单 6 直接显示运行状态：服务是否运行、运行模式、隧道网卡与地址、已连接节点数、Web 管理端地址、局域网转发状态。
- 安装时一并安装 `easytier-cli`，用它查询真实的节点连接与路由信息（对端、延迟、丢包、隧道类型、代理网段），而不是只看服务有没有在跑。
- 支持 `et --version` 查看版本，`et --diag` 在非交互环境下一次性输出运行状态、服务管理器信息、进程与最近日志，便于远程排障（不含 `config.toml`，不会泄露网络密钥）。
- 界面按语义着色（标题、信息、警告、错误、状态行）；输出不是终端或设置了 `NO_COLOR` 时自动禁用颜色，日志与管道输出保持纯文本。
- 卸载程序和服务，可选择保留或删除数据。

## 安装模式

| 模式 | 适用场景 | 说明 |
| --- | --- | --- |
| 核心 + 本地 Web 管理端 | 设备资源较充足，希望在本机使用 Web 管理 | 安装 EasyTier 核心和 Web 组件，资源占用相对较高 |
| 仅核心 + 本地 TOML 配置 | 低闪存设备或偏好手动编辑配置 | 只安装核心；编辑配置后再启动服务 |
| 仅核心 + 远程 Web 控制台 | 设备资源有限，希望由其他设备提供 Web 管理 | 本机运行核心，并连接远程配置服务 |

首次安装默认选择轻量的“仅核心 + 本地 TOML 配置”模式。需要在设备本机使用 Web 管理时，请在安装菜单中选择本地 Web 模式。

本地配置文件路径：

```text
/opt/easytier/data/config.toml
```

本地 Web 模式默认端口：

- Web/API 端口：`11211`
- 配置服务 UDP 端口：`22020`
- 节点端口默认值：`11010`

请根据实际网络环境检查端口占用和防火墙策略，不要把 Web/API 管理端口直接暴露给不可信网络。

本地 Web 模式还需要一个 **Web API 访问地址**，它告诉 Web 页面去哪里调用本机 API：

- 必须是**浏览器打开页面时实际使用的地址**（例如用 `http://192.168.1.40:11211` 打开页面，就填 `192.168.1.40`）。
- 安装时会给出检测到的地址作为默认值，请确认或改成你实际使用的地址；设备有多个网段时（例如同时存在 `192.168.100.1` 和 `192.168.1.40`），要填浏览器所在网络能访问的那一个。
- 安装完成后脚本会通过 HTTP 自检页面和 `/api_meta.js` 公布的地址，不一致会直接提示安装未完成。
- 浏览器会记住以前用过的地址；如果更换过地址，请清除该站点数据或用无痕窗口打开。

## 菜单功能

| 选项 | 功能 |
| --- | --- |
| 1 | 安装 EasyTier，并选择运行模式 |
| 2 | 更新 EasyTier 核心/组件 |
| 3–5 | 启动、停止、重启服务 |
| 6 | 查看运行状态（服务 / 隧道 / 节点连接 / 局域网转发） |
| 7 | 查看日志 |
| 8 | 修改运行参数（端口 / Web API 地址 / 局域网转发） |
| 9 | 更多配置（二级菜单：编辑本地 TOML / 远程 Web 配置服务器 / 下载源与镜像 / 更新管理脚本） |
| 10 | 卸载 EasyTier（二级菜单：保留 `et` 管理脚本 / 全部卸载） |
| 0 | 退出 |

主菜单的常用操作（安装、更新、启停、状态、日志、运行参数）都在一级；低频的配置与维护集中在菜单 9。菜单 6「查看运行状态」等同于 `et --diag` 的运行状态部分。

在本地 TOML 配置模式下，安装完成后服务会保持停止状态，也不会自动启用开机启动。请先编辑并保存 `config.toml`，再从菜单选择“启动服务”。后续修改配置后，选择“重启服务”使其生效。

## 系统与依赖

脚本会尝试适配以下服务管理环境：

- OpenWrt / ImmortalWrt（procd）
- 使用 systemd 的 Linux
- OpenRC
- 部分 SysV / BusyBox init 环境

脚本使用 `curl` 或 `wget` 下载文件，并需要 `unzip` 解压 Release 压缩包。若缺少 `unzip`，脚本会尝试调用系统包管理器安装；自动安装失败时，需要手动安装依赖。安装组件和创建系统服务需要 root 权限。

脚本包含常见架构映射，例如 `x86_64`、`aarch64`、`armv7`、`armv6`、`i686`、`mips`、`mipsel`、`mips64el`、`riscv64`。最终是否有匹配的可用二进制，以 EasyTier 官方 Release 的实际资产和设备 ABI 为准。

## 下载源与镜像

菜单中的“下载源 / 镜像加速设置”可配置 GitHub 镜像前缀。核心 Release 下载按以下顺序尝试：

1. Gitee 上对应的 EasyTier Release 资产。
2. 配置的 GitHub 镜像。
3. GitHub 官方 Release。

获取最新版本信息时，脚本优先解析 Gitee 的 Release 页面；无法取得版本号时，再尝试 GitHub 镜像 API 和 GitHub 官方 API。下载后会检查 ZIP 完整性；如果获取到 SHA-256 校验文件，也会验证摘要。若 Gitee 上没有校验文件，会提示并跳过独立哈希校验，但仍会执行 ZIP 完整性检查。

默认镜像前缀为：

```text
https://github.chenc.dev/
```

镜像前缀需要能够代理脚本拼接出的完整 GitHub URL。也可以在菜单中选择官方源，清除自定义镜像。通用下载镜像通常只代理 Raw 文件或 Release 资产，不保证支持 GitHub API。因此菜单中的连通性测试只下载并校验安装脚本的 Raw 文件，不请求 GitHub API；核心下载仍会按配置的顺序逐源回退。选择官方源时，则测试 GitHub 官方 Raw 地址。

## 安装脚本自更新

脚本默认从以下仓库更新管理脚本：

```sh
SCRIPT_REPO="jhbook/easytier-installer"
SCRIPT_BRANCH="main"
SCRIPT_PATH="easytier.sh"
```

在菜单中选择“更新安装脚本”后，脚本会尝试使用已配置的镜像下载 Raw 文件；镜像下载失败或返回内容无效时，回退到 GitHub 官方 Raw 地址。替换前会检查文件非空、脚本标识和 `sh -n` 语法，并尝试备份旧文件为 `.bak`。 更新成功后会自动重新执行更新后的脚本，直接进入最新版菜单，无需退出再手动运行 `et`。

持久化管理脚本路径为：

```text
/usr/bin/et
```

如果该路径已存在且不像本项目脚本，为避免覆盖其他程序，首次安装不会强行替换它。此时请检查冲突文件，确认后再处理。

## 常用路径

| 路径 | 用途 |
| --- | --- |
| `/opt/easytier/bin/` | EasyTier 核心与 Web 组件 |
| `/opt/easytier/data/` | 本地配置与运行数据 |
| `/etc/easytier-installer/settings` | 安装管理脚本的设置 |
| `/etc/easytier-installer/run.sh` | 服务运行包装脚本 |
| `/usr/bin/et` | 持久化管理脚本入口 |

具体文件会随运行模式和系统类型变化，并非每台设备都会拥有表中全部文件。

## 服务与日志

可以直接在管理菜单中启动、停止、重启服务，查看运行状态和日志。也可根据系统使用相应日志工具，例如：

```sh
# systemd 系统
journalctl -u easytier -f

# OpenWrt / ImmortalWrt
logread -e easytier
```

实际服务名称和日志位置可能随系统环境而异。

## 局域网转发（OpenWrt / ImmortalWrt）

在 OpenWrt / ImmortalWrt（fw4 防火墙）上安装完成后，脚本会询问是否允许局域网设备访问 EasyTier 网络：

- 选择“是”时，脚本会为 EasyTier 的虚拟网卡准备防火墙区域、开启 NAT（masquerade）并添加“局域网 → 该区域”的转发规则。不这样做时，局域网设备的流量会被 fw4 的默认转发策略拒绝，表现为 ping 不通或提示“无法连到端口”，看起来像 EasyTier 没有运行。
- 虚拟网卡已经属于某个防火墙区域时会直接复用该区域，不会重复叠加区域；重复执行保持幂等。
- 脚本会把 EasyTier 区域的**入站策略设为 `ACCEPT`**；复用时若发现该区域入站策略是 `REJECT`/`DROP`，会自动改为 `ACCEPT` 并把原值记入 `LAN_FORWARD_INPUT_PREV`，卸载时恢复。入站策略若保持 `REJECT`，隧道里回来的 TCP 应答会被防火墙复位，ICMP 不受影响，表现为 **ping 通、但隧道内所有 TCP 服务都打不开**。
- 配置写入 `/etc/config/firewall` 并立即重载，重启后依然有效。非 fw4 防火墙会自动跳过本项。

菜单 6「查看运行状态」会显示当前是否已启用局域网转发。

卸载时脚本只撤销自己添加的内容：脚本创建的区域会被删除；由你手工创建的防火墙区域会保留，原本就存在的转发规则也不会被删除。

## 子网代理

子网代理让 EasyTier 网络里的其它节点能够访问本机后面的局域网（例如本机的 `192.168.6.0/24`）。

本脚本**不提供**子网代理的设置入口 —— 它只在一个地方配置，避免菜单与配置文件两处不一致：

- **本地 TOML 模式**：写进 `/opt/easytier/data/config.toml`（菜单 9 的选项 1 可直接编辑）。需要公布多个网段时，重复写多段 `[[proxy_network]]` 即可：

```toml
[[proxy_network]]
cidr = "192.168.6.0/24"

[[proxy_network]]
cidr = "10.200.1.0/24"
```

- **本地 Web / 远程 Web 模式**：在 Web 管理端的网络设置里配置。

改完后重启服务（菜单 5）生效。菜单 6「查看运行状态」里的「路由与代理网段」会列出本机与各节点公布的 `proxy_cidrs`，可以用它确认是否真的生效。

## 卸载说明

菜单 10 会进入卸载二级菜单，先显示核心、Web 管理端、配置目录与数据目录的当前状态，再选择：

- **1. 卸载 EasyTier（保留 `et` 管理脚本）**：停止服务并取消开机自启，删除服务定义、核心与 Web 二进制，以及 `/opt/easytier` 和 `/etc/easytier-installer` 下的配置与数据库；保留 `/usr/bin/et`，之后可直接运行 `et` 重新安装。
- **2. 全部卸载（含 `et` 管理脚本）**：在第 1 项的基础上，同时删除 `/usr/bin/et`（含 `et.bak` 与残留的临时副本）。卸载完成后脚本会直接退出。

两种方式都会先停止服务、取消开机自启、清理各 init 系统的服务定义与开机链接，并结束残留的 EasyTier 进程，因此不会留下指向已删除文件的旧定义。删除 `/usr/bin/et` 前会先确认文件内容确实属于本安装脚本，避免误删其他程序。

卸载前请确认是否仍需要 `config.toml`、数据库和其他运行数据。建议先备份重要配置。

## 故障排查

- **提示缺少下载工具**：安装 `curl` 或 `wget` 后重试。
- **提示缺少 `unzip`**：手动安装 `unzip`，再运行安装菜单。
- **下载失败**：在菜单中更换镜像或切换到官方源；确认设备能访问相应站点。
- **菜单直接退出**：确认是在交互式 SSH/终端中运行，并使用“下载到文件再执行”的命令。
- **本地配置模式无法启动**：检查 `/opt/easytier/data/config.toml` 是否已填写有效配置；基础检查不等于完整 TOML 语法验证。
- **没有匹配的 Release 资产**：确认设备 CPU 架构、ABI 与 EasyTier 官方发布的二进制相符。
- **`et` 命令不存在**：确认首次运行有 root 权限，且 `/usr/bin` 位于 `PATH`；也可以运行 `/usr/bin/et`。

## 安全与测试说明

- EasyTier 的网络名称、密钥和配置应妥善保管，不要公开包含敏感信息的配置文件。
- 不要将 Web/API 管理接口暴露到公网；跨网管理应配合可信组网、访问控制和防火墙。
- 执行脚本前请审查来源和内容；生产设备升级前先备份配置。
- Shell 语法检查和压缩包完整性检查不代表已在所有设备上完成实测。请先在测试设备验证安装、启动、联网、更新与卸载流程。

菜单会显示当前安装脚本版本号。菜单 9 的选项 4 更新安装脚本时，按以下顺序尝试并在每一步检查脚本身份与 Shell 语法：

前一个来源下载失败或校验不通过时才会继续尝试下一个来源。下载地址不追加时间戳查询参数，以兼容不支持额外查询参数的镜像/CDN；脚本通过校验下载内容来判断是否可用。

## 版本说明（v0.5.1）

- 移除菜单里的子网代理入口与 `PROXY_NETWORKS` 设置项。子网代理改成只在**一个地方**配置：本地 TOML 模式写 `config.toml` 的 `[[proxy_network]]`，Web 模式在 Web 管理端设置。此前菜单与配置文件两处都能配，容易混淆。
- 脚本不再向核心传 `--proxy-networks`，因此不会与 `config.toml` 里的设置产生分叉。实测：只在 `config.toml` 写入 `172.30.0.0/24` 时，核心命令行不含该参数，`easytier-cli route` 依旧正常公布该网段；`run.sh` 里已无相关引用。
- 菜单 8「修改运行参数」由六项减为五项：节点端口、Web/API 端口、配置服务器端口、Web API 地址、局域网转发开关。

## 版本说明（v0.5.0）

- 新增子网代理设置入口（菜单 8 选项 5），可填写多个网段；该值以 `--proxy-networks` 传给核心，本地 Web、本地 TOML、远程 Web 三种模式都会带上，并与配置文件里的 `[[proxy_network]]` 合并累加（脚本不改写 `config.toml`）。**该入口已在 v0.5.1 移除，改为只在配置文件或 Web 管理端设置。**
- 菜单 8 扩展为「修改运行参数」，包含节点端口、Web/API 端口、配置服务器端口、Web API 地址、子网代理网段和局域网转发开关六项；在不适用的模式下会解释原因，而不是直接拒绝。（v0.5.1 起为五项。）
- 新增局域网转发的手动开关：菜单 8 可随时开启或关闭，不必重新安装。
- 主菜单从 13 项压缩为 10 项：启停、状态、日志、运行参数保留在一级，低频的编辑 TOML、远程 Web、下载源、更新管理脚本合并进菜单 9「更多配置」二级菜单。

- 修复 `WEB_API_HOST` 填成 `http://1.2.3.4`、`1.2.3.4/` 或 `1.2.3.4:11211` 时会拼出 `--api-host http://http://…` 的问题，录入时会自动规范化为纯地址。

- 可移植性修复：把 7 处 GNU BRE 扩展 `\|` 改为 `grep -qE` 加 `|`，避免在部分 libc 上把「或」当成字面量，导致脚本自更新误报「内容无效」。

## 版本说明（v0.4.8）

- 修复隧道内「只能 ping 通、无法访问」的问题：EasyTier 防火墙区域的入站策略不再使用 `REJECT`，改为 `ACCEPT`。入站策略为 `REJECT` 时，隧道里回来的 TCP 应答会被防火墙复位，而 ICMP 不受影响，所以表现为 ping 通、但隧道内任何 TCP 服务都打不开。
- 复用已有防火墙区域时，若该区域入站策略是 `REJECT`/`DROP`，脚本会自动改为 `ACCEPT`，并把原值记入 `LAN_FORWARD_INPUT_PREV`，卸载时恢复原策略。
- 菜单 11「查看运行状态」在入站策略为 `REJECT`/`DROP` 时会给出提醒。
- 主菜单顶部新增运行状态摘要：服务是否运行、运行模式、隧道网卡与地址、已连接节点数、Web 管理端地址、局域网转发状态。
- 「查看运行状态」新增节点连接与路由信息（对端、延迟、丢包、隧道类型、代理网段），数据来自 `easytier-cli`。
- 安装时会一并安装 `easytier-cli`；该组件缺失或无法运行时只提示，不影响核心安装。
- 界面加入颜色：标题、信息、警告、错误和状态行按语义着色；输出不是终端或设置了 `NO_COLOR` 时自动禁用，日志与管道输出保持纯文本。
